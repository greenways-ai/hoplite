Hoplite installations contain two commands:

- `hoplite` provides the REPL, build, check, package, authentication, management, and service lifecycle commands.
- `hoplite-server` runs a previously built application without retaining the control plane in production memory.

## Homebrew

Use the fully qualified formula name. Homebrew installs the current Hoplite
release and trusts only the Greenways tap entry you selected.

```sh
brew install greenways-ai/tap/hoplite
hoplite version
hoplite-server version
```

## Install script

On macOS or Linux, install the published executables without a package manager:

```sh
curl -fsSL https://raw.githubusercontent.com/greenways-ai/hoplite/main/packaging/scripts/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
hoplite version
hoplite-server version
```

Set `HOPLITE_INSTALL_DIR` to choose another destination:

```sh
curl -fsSL https://raw.githubusercontent.com/greenways-ai/hoplite/main/packaging/scripts/install.sh \
  | HOPLITE_INSTALL_DIR=/usr/local/bin sh
```

## Create the starter application

The starter script writes a minimal `app.hal` and `project.edn`; it does not
clone or build Hoplite.

```sh
curl -fsSL https://raw.githubusercontent.com/greenways-ai/hoplite/main/packaging/scripts/new-app.sh | sh -s -- hello
cd hello
hoplite serve foreground --mode dev .
```

In another terminal:

```sh
curl -i http://127.0.0.1:8080/hello
```

## Run the production server

Build output is immutable input to the slim serving plane:

```sh
hoplite serve build --mode prod .
hoplite-server .
```

`hoplite-server` validates `.hoplite/conf/nginx.conf`, materializes its stripped
embedded Nginx/Hara server when necessary, and replaces itself with Nginx. The
compiler, REPL, package tools, authentication store, and management gateway are
not retained in the production process tree.

## Run the published container

```sh
docker run --rm -p 8080:8080 ghcr.io/greenways-ai/hoplite:latest
curl -i http://127.0.0.1:8080/hello
```

The image builds the example application in its builder stage. Its final stage
contains only `hoplite-server`, the compiled application output, and required
native libraries.

## Platform support

| Platform | Status | Distribution |
| --- | --- | --- |
| macOS arm64 | Supported | Homebrew and standalone executables |
| macOS Intel | Supported | Homebrew and standalone executables |
| Linux arm64 | Supported | Homebrew, installer, executables, and OCI image |
| Linux x86-64 | Supported | Homebrew, installer, executables, and OCI image |
| Windows | Unsupported | No supported host lifecycle integration |

:::note[Building Hoplite itself]
Source builds are a contributor workflow, not the product installation path.

:::
